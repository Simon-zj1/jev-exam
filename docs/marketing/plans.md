# 宣传方案（三套，按投入从低到高）

前提：这是一个个人项目，没有预算、没有团队、目标用户是**不懂 AI 的国内备考人群**，
同时你还想用它应聘 AI 应用开发工程师。所以宣传必须一次做两件事：
**获客**与**建立技术可信度**。下面三套方案分别押注不同的东西，建议按 A → B → C 的顺序做。

---

## 方案 A：公开基准，把「可信」做成产品（技术品牌，0 成本）

**押注**：个人开发者能做出的最强技术资产，不是功能列表，而是一个**可复现的公开评测**。
学 `alibaba/open-code-review` 的 AACR-Bench：数据 + 脚本 + 门槛 + 榜单。

**已有基础**：`eval/golden/subjective.jsonl`（12 题 / 42 个标注点）、
`npm run benchmark`、[docs/benchmark.md](../benchmark.md)。

**要做的事**

1. 把金标准集扩到 60–100 题（用产品自己的纠错回流：`npm run feedback:golden`）。
2. 写一篇《为什么「一句话说没说中一个要点」值得单独做一个基准》——把标注入门讲清楚，
   邀请别人提 PR 加标注。
3. 在 README 顶部放一张成绩表，把 `typesafe`（Jev）那一行留空并写明复现命令，
   谁有 key 谁就能填。

**衡量**：GitHub star 增量、被引用的次数、有多少人提 PR 补标注。

**为什么对你特别合适**：面试 AI 应用岗时，这张表比任何功能截图都有说服力——
它证明你知道「AI 应用的质量要怎么量化」。

---

## 方案 B：内容获客，写「AI 备考方法论」而非产品介绍（国内平台，低成本）

**押注**：目标用户不搜「Jev 备考」，他们搜的是「考研 怎么知道自己哪里不会」
「背了就忘怎么办」。产品介绍没人看，方法论有人看。

**选题（每篇都从痛点出发，产品只在文末出现一次）**

| 选题 | 核心内容 | 对应产品能力 |
| --- | --- | --- |
| 《你以为你读懂了，其实只是眼熟》 | 主动回忆 vs 重复阅读的实验结论 | 出题自测 |
| 《错题本为什么没用》 | 记录了 ≠ 记住了；间隔重复的三要素 | FSRS 排期 |
| 《为什么「感觉复习完了」是错觉》 | 掌握度需要可测量的代理指标 | 逐点判定 + 掌握度 |
| 《AI 帮我复习，但它判错了我怎么办》 | 生成式 AI 在教育场景的信任问题 | 待复核 + 纠错回流 |

**关键动作**：每篇文章配一张**可自查的图**（比如「覆盖率 11/14，未覆盖的三句是哪三句」），
让读者能在自己的材料上复现同一件事。这个方法论的原创性不在观点，在**可复现**。

**平台**：你的技术博客（已有，SEO 归你）+ 小红书/知乎（目标用户在那里，但要注意别写成技术文）。

**衡量**：不是阅读量，是「有多少人真的上传了自己的材料」。

---

## 方案 C：可分享的自测结果（增长闭环，中成本）

**押注**：备考人群最强的分享动机是**晒努力**与**晒成果**。
现在的结果页是私有的，没有任何对外分享能力——这既是隐私优点，也断了传播。

**做法**：做一个**只包含统计、不含原文**的分享卡：

```
我的《传播学教程》薄弱点地图
覆盖率 78%   待复核 3 题
最弱三个知识点：议程设置 / 沉默的螺旋 / 框架理论
—— 材料只在我自己的账号里，这张图不含任何原文
```

要点：

1. **必须默认脱敏**：只出知识点名与百分比，绝不出材料原文、题干、作答。
   这与你已经写进 [terms](../../src/app/terms/page.tsx) 的「不提供公开分享」并不冲突——
   分享的是统计图，不是内容，但要在条款里写清楚这条边界。
2. **分享卡要好看**：这是它能不能被转发的唯一原因。可以直接复用报告页的排版语言。
3. **带回来一个钩子**：图上写「用我自己的笔记生成」，而不是写产品名。

**风险**：知识点名本身可能泄露材料主题（比如「第三章 内部劳动规则」）。
所以分享前必须让用户**勾选**要显示的知识点，默认全不勾。宁可转化低，也不能泄露。

**衡量**：分享率（生成分享卡的用户 / 完成一次自测的用户），以及分享带来的新注册。

## 三套方案的顺序与成本

| 方案 | 成本 | 见效速度 | 主要产出 |
| --- | --- | --- | --- |
| A 公开基准 | 低（主要是标注时间） | 慢，但复利 | 技术可信度、简历资产 |
| B 内容获客 | 低（写作时间） | 中 | 真实用户 |
| C 分享卡 | 中（一个功能 + 设计） | 快，但有隐私风险 | 传播闭环 |

我的建议：**先做 A 的一小步**（把 doc 写好、把榜单那行空着），
**再做 B**（内容是最便宜的获客），**C 放到有真实用户之后**——
没有人愿意为一张没有数据的薄弱点图做分享，冷启动阶段做分享卡是浪费。

## 一句话定位（三套方案共用）

> 把你自己的材料变成一场可核对的考试：每一分都能指回原文，判不准的题会说出来，
> 错题按记忆曲线排期，数据随时可以带走。

这句话要同时出现在：落地页首屏、GitHub 仓库描述、简历的项目一句话里。
